# Today (Notion ⇄ Google Calendar) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A "Hari ini" tab in the notch: today's lessons and close deadlines, with Notion tasks you can tick or add.
- Pill hints for the next lesson and for deadlines.
- Two-way sync of the Notion timetable and tasks with Google Calendar, through Dank Calendar (`dcal`).

**Architecture:**
- **Pure logic** lives in ES modules under `today/`, tested with `node --test`:
  - `timetable.mjs`: parsing `Jam` and `Hari`, and the lessons of a day;
  - `notion.mjs`: finding the right databases and columns, and normalising rows;
  - `deadlines.mjs`: due-soon and clash labels;
  - `sync.mjs`: a pure two-way reconciler that turns both sides plus the last snapshot into a list of
    actions.
- **QML services** do the I/O:
  - `DcalService.qml` runs `dcal ipc … --json` through `Process`;
  - `NotionDbService.qml` talks to the Notion REST API with `XMLHttpRequest`;
  - `TodayService.qml` ties them together: data, the sync loop, the first-sync preview, conflicts,
    nudges and the morning open.
- **UI:** `NotchToday.qml` is the fifth notch tab. There's also a settings page, a CLI and IPC.

**Tech Stack:**
- Quickshell 0.3.2 and Qt 6.12.
- Node 26 (`node --test`).
- Dank Calendar 1.6.1 (`dcal ipc`), already logged in to the user's Google account.
- Notion API `2022-06-28`, using the existing token at `~/.config/islet/notion-token`.

**Spec:** `docs/superpowers/specs/2026-10-21-finder-and-today-design.md`, Part 2. The approved mockup is
`docs/superpowers/specs/mockups/2026-10-21-today-tab.html`.

- **Tasks:** 3 rows, all "To do".

- **dcal:**

## Global Constraints
- **All Google access goes through `dcal`.** No Google OAuth in Islet. Google Classroom calendars are
  read-only and are only displayed.
- **Two-way sync.**
  - **Conflict rule:** a conflict is the same item changed on both sides between two syncs. The last
    edit wins, and the user is **always told**: a notification plus a conflict list (kept 7 days) with
    a "Pakai versi yang satunya" button.
  - **Edit times:** a Google-side change is timestamped when Islet first sees it; the Notion side uses
    `last_edited_time`.
- **Timetable rules:**
  - Each row is a weekly series, starting in the week of the first sync, with no end unless
    `todaySemesterEnd` is set.
  - Moving the series in Google writes Hari and Jam back to Notion; a single-occurrence edit stays a
    Google-only exception.
  - A row deleted in Notion ends its series (`UNTIL` = yesterday).
  - A series deleted in Google never touches Notion: the row is unlinked and listed as "Removed in
    Google", with **Put it back** and **Remove from Notion** (trash).
- **Task rules:**
  - `Rencana Mulai` becomes an event: date-only means all-day; a time without an end gets
    `todayEventMinutes` (default 60).
  - Moving or retitling the event writes back to Notion.
  - Done adds a "✓ " title prefix.
  - Deleting the event in Google clears `Rencana Mulai`, but only after it has been missing for **2
    syncs in a row** while dcal is healthy.
  - `Tenggat` is not an event.
  - `GCal ID` stores the event id.
- **Safety:**
  - Islet only edits or deletes events whose description contains its tag `islet-notion:<pageId>`.
  - The first sync shows a preview ("akan membuat N event") and runs only after the user confirms.
  - There's a dry-run CLI (`islet today preview`).
  - Never change the Notion schema without asking the user.
- **Today tab:**
  - Lessons come only from the Notion timetable; Classroom events count only as deadlines (they can't
    be ticked).
  - Deadlines: tasks not Done with `Tenggat` within `todayDays` (default 7). Overdue tasks come first,
    in red.
  - Labels: "hari ini HH.MM" (or just "hari ini" for date-only), "besok", "<Hari singkat>, N hari", and
    "terlambat N hari" (overdue).
  - Ticking a task sets Status = Done, optimistically with rollback.
  - "＋ tugas baru" creates a Tasks row with Tipe = Sekolah.
  - "bentrok" labels go on items that overlap in time; no notification for those.
- **Pill priority:** toast > a lesson starting within 5 minutes ("Mapel · mulai 5 mnt lagi") > song > a
  deadline due today when idle. While music plays, a small "N tenggat" counter.
- **Notifications:**
  - No duplicates of dcal's event reminders.
  - A morning summary at the first activity of the day, and one nudge 3 hours before a timed deadline.
    Both can be turned off (`todayNudges`).
- **Morning open:** at the first user activity after 04:00 each day, the notch opens to Today for
  `todayMorningSeconds` (default 8).
- **Sync timing:** every `todaySyncMinutes` (default 5), shortly (about 3 s) after a change made from
  Islet, and on demand. The last sync time and any errors show in the tab header and on the settings
  page.
- **CLI and IPC:** `islet today [sync|preview|status|add "text"]`; IPC target `today`.
- **Settings:** one page, "Calendar & Notion", that detects everything:
  - Google shows as "Connected via Dank Calendar ✓", or a `dcal show` button.
  - Notion databases are pre-selected, and the column mapping has dropdowns to fix it.
  - Every row is searchable ("google", "notion", "jadwal", "tugas", "deadline").
- **Idle cost:** 0% CPU. No per-frame work; only timers and short-lived processes.
- **Secrets:** the Notion secret never goes in logs, argv or URLs. Helper Python, if any, runs with
  `python3 -I`.
- **Live testing:** save any setting changed in tests with `islet get` and restore it. Any write to the
  real Google calendar or the real Notion databases needs the user's go-ahead in chat. Use the local
  dcal test calendar from Task 1 for write tests.

## Review Focus
1. **dcal unreachable, logged out (`needs_reauth`), or partly failing during a sync.** It must never
   count as "the event was deleted in Google", never clear Notion fields, and must show "Google: perlu
   login ulang di Dank Calendar" (Task 5: `missing events are not deletions when dcal is unhealthy`).
2. **The same Notion row edited during a sync (Islet's own write echoes back).** It must not count as a
   conflict or loop forever. The snapshot is updated from what Islet wrote (Task 5:
   `own writes do not echo as conflicts`).
3. **Midnight and time zones:** a date-only Tenggat "today" in UTC+7 at 00:30 local, an all-day event's
   exclusive end, and lessons for "today" right after midnight. Everything is local time (Task 2 and
   Task 4: tests at 00:30 +07:00).
4. **A user-made event that happens to carry the same title as a Notion task** must not be adopted, edited
   or deleted. Only tagged events are Islet's (Task 5: `untagged events are never touched`).
5. **A Notion rate limit (429) or offline Notion mid-sync:** partial progress is kept, nothing is applied
   twice, and the next sync resumes. Actions are idempotent because of the GCal ID and the tag (Task 6:
   retry-after; Task 8: apply skips actions already done).

### Task 3: Notion detection and normalising

**Files:** Create `today/notion.mjs`. Test: `tests/today-notion.test.mjs`, plus fixtures in
`tests/fixtures/notion-*.json`. The fixtures are hand-written to match the facts above and hold no real
content.

**Interfaces:**
- `classify(db: {id, title, properties: {name: {type}}, last_edited_time}): {kind: "timetable"|"tasks"|null, score: number}`.
  - **Timetable** needs a select whose options look like weekday names, plus a text or rich_text
    property whose name matches /jam|waktu|time/i.
  - **Tasks** needs a title, a status (or a select named Status), and at least one date property.
  - Score bonuses go to databases with the expected names ("Jadwal Pelajaran", "Tasks") and to recent
    edits.
- `pickDatabases(dbs[]): {timetable: id|"", tasks: id|""}`: the highest score of each kind.
- `mapColumns(kind, properties): object`.
  - For a timetable: `{title, hari, jam, mapel, guru}`.
  - For tasks: `{title, status, start, due, priority, type, gcal}`.
  - Matching goes by type first, then by name: `start` /rencana|mulai|start|plan/i, `due`
    /tenggat|deadline|due/i, `gcal` /gcal|google/i.
  - Unmatched fields are `""`.
- `lessonFromRow(row, map, mapelTitles: {pageId: title}): Lesson | {error, pageId}`.
- `taskFromRow(row, map): Task`, where `Task = {pageId, title, status, done, start, startHasTime, end,
  due, dueHasTime, priority, type, gcalId, edited}`. `done` is true when the status belongs to the
  "complete" group or is named Done or Selesai.
- `taskPatch(map, fields): object`. Builds a Notion `properties` patch for `{status, start, end,
  allDay, title, gcalId}`; unset fields are left out.

### Task 4: Deadlines and clashes

### Task 5: The two-way reconciler

**Files:** Create `today/sync.mjs`. Test: `tests/today-sync.test.mjs`.

**Interfaces:**
- `TAG = "islet-notion:"`. `tagOf(description): pageId | ""`.
- `plan({lessons, tasks, events, state, now, healthy, opts}): {actions, state}`.
  - **Inputs:**
    - `lessons: Lesson[]` and `tasks: Task[]` come from Tasks 2 and 3.
    - `events: Ev[]` are the series and single events in Islet's target calendar. Occurrences are
      collapsed to their series (Task 1 says how).
      `Ev = {id, title, start, end, allDay, description, recurring: bool}`.
    - `state = {pairs: {[pageId]: {eventId, kind, snap: Fields, missing: number, notionEdited}},
      removed: [...], conflicts: [...]}`.
    - `opts = {seriesFrom: Date, semesterEnd: "", eventMinutes: 60}`.
  - **Actions** (plain objects, applied in order by Task 8):
    - `{op:"createEvent", pageId, kind, fields}`
    - `{op:"updateEvent", eventId, fields}`
    - `{op:"endSeries", eventId, until}`
    - `{op:"updateNotion", pageId, kind, fields}`
    - `{op:"clearStart", pageId}`
    - `{op:"setGcalId", pageId, eventId}`
    - `{op:"conflict", pageId, title, used:"google"|"notion", other: Fields}`
    - `{op:"removedInGoogle", pageId, title}`
  - `Fields`:
    - for a lesson: `{title, hari, start, end}`;
    - for a task: `{title, start, end, allDay, done}`.
    - Event titles use the "✓ " prefix for a done task, and descriptions carry `TAG + pageId`.
  - **Rules:** the Global Constraints, exactly. Change detection compares each side with `snap`:
    - Notion changed and Google didn't: update the event.
    - Google changed and Notion didn't: update Notion.
    - Both changed with different values: a conflict, where the later edit wins. The Google edit time
      is `now`, because it's first seen now; the Notion one is `notionEdited` from `last_edited_time`.
  - **New state:** after the actions succeed, `snap` = the winning fields. That's how own writes don't
    echo back.

- [ ] **Step 1: Write the failing tests**, one per rule, each built from small literal inputs:
  - `new lesson creates a weekly series from this week`: `fields` carries `BYDAY` and `seriesFrom`.
  - `new task with Rencana Mulai creates an all-day event and sets GCal ID`.
  - `Notion change updates the event`, and `Google change updates Notion`.
  - `both changed → last edit wins, conflict reported`, tested both ways round.
  - `own writes do not echo as conflicts`: run `plan` twice, the second time with the outputs of the
    first applied; it gives no actions.
  - `row deleted in Notion ends the series (UNTIL yesterday)`.
  - `series deleted in Google never touches Notion`: gives `removedInGoogle` and an unlinked pair.
  - `task event missing once does nothing, twice clears Rencana Mulai`.
  - `missing events are not deletions when dcal is unhealthy`: with `healthy:false`, no clearStart and
    `missing` is not counted.
  - `untagged events are never touched`: an event with the same title but no tag isn't adopted.
  - `done task gets ✓ prefix; undone removes it`.
  - `task without Rencana Mulai has no event; clearing it in Notion deletes Islet's event`. That last
    case is a deliberate Notion-side change, so `{op:"deleteEvent", eventId}` (add it to the list).
- [ ] **Step 2:** Run `TZ=Asia/Jakarta node --test tests/today-sync.test.mjs`. Expected: FAIL.
- [ ] **Step 3:** Implement `plan` as a pure function. It must not mutate the input state; it returns
  a new one.
- [ ] **Step 4:** Run `node --test tests/`. Expected: all PASS.
- [ ] **Step 5: Commit:** `git commit -m "Today: two-way reconciler"`.

### Task 8: Sync apply loop, preview and conflicts

**Files:** Modify `TodayService.qml`, `shell.qml`, `bin/islet`.

**Interfaces:**
